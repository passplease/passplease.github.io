之前安装[PrivadoVPN](../Ubuntu梯子/#加装privado-vpn)的时候触及到了Linux的梯子配置，但是当时我也才第一次使用Linux，并不熟悉。而今我已经彻底转向Linux，把Windows几乎全部卸载，也对网络有更多了解了，再次安装梯子也确实有价值再重新写一写笔记了。<br><br>
## 流量流向
以前的方案中流量首先会经过**smartdns**进行标记，标记是否匹配了**nft**规则，如果匹配就会打上标记，随后由**WireGuard**根据标签控制要不要走代理。<br><br>
而这次我计划选用**Mihomo**，作为**Clash**衍伸产品，他自带域名分流功能，同时Linux上用TUN模式做系统网络出口还能看到来源程序，并根据程序打标签，做到程序标签分类。尤其是进程级别的功能是**smartdns**所不支持的，所以我这次直接选他就搞定了。同时他自带**WireGuard**，完全不需要其他软件。

## 配置
**Mihomo**使用`config.yaml`配置，默认路径在`/root/.config/mihomo/config.yaml`{: .filepath} ，官方教程在[这里](https://wiki.metacubex.one/config/)，官方给了一个大而全的配置文件，其中写自己的内容就好了，具体也就是改他的配置文件。由于条目特别多，我是借助deepseek在写，自己写太麻烦了。写完之后可以用
```bash
sudo mihomo -d /etc/mihomo -t
```
检查是否配置文件是否正确，其中`-d`指向配置文件，`-t`表示运行检查。其中如果要启用`TUN`模式就必须设置开启`tun.enable: true`<br><br>
配置中可以使用`GEOSITE,cn,DIRECT`和`GEOIP,CN,DIRECT`这种工具根据域名IP地址在哪来决定怎么转发、要不要过梯子，不过代价是启动会需要更新这些数据，官方配置文件中有如下部分可以设置镜像（因为连不上）还有其他配置
```yaml
#自定义 geodata url
geox-url:
	geoip: "https://fastly.jsdelivr.net/gh/MetaCubeX/meta-rules-dat@release/geoip.dat"
	geosite: "https://fastly.jsdelivr.net/gh/MetaCubeX/meta-rules-dat@release/geosite.dat"
	mmdb: "https://fastly.jsdelivr.net/gh/MetaCubeX/meta-rules-dat@release/geoip.metadb"

geo-auto-update: true # 是否自动更新 geodata
geo-update-interval: 24 # 更新间隔，单位：小时

# Matcher implementation used by GeoSite, available implementations:

# - succinct (default, same as rule-set)

# - mph (from V2Ray, also `hybrid` in Xray)

# geosite-matcher: succinct
```
## 添加程序
虽然**Mihomo**可以根据进程名称进行匹配，但是首先你得指定对应程序的进程名称，这个用程序名查看指令就好了，多半都找得到。
```bash
pgrep -l （程序名）
```
## 踩坑
### DNS
DNS可以说是我这两次配置都最烦人的点了，每次都出循环问题。实际上这个问题我折腾了一上午，结果最后问题很简单，关键是学校的网居然连不上1.1.1.1和8.8.8.8，导致国外域名解析的时候根据我的配置会走这两个服务器，但是又连不通，就会导致DNS解析全部失败。
>这个地方千万不要相信什么AI说的去调路由表，什么`ip rule`什么的乱七八糟命令，都不对，**Mihomo**会覆盖路由表，你调什么都没有用，纯粹浪费时间
{: .prompt-warning }

解决方案是让1.1.1.1和8.8.8.8流量都走代理，首先DNS内配置
```yaml
respect-rules: true    # 关键：让 DNS 查询遵循rules
proxy-server-nameserver: # 专用于解析代理的DNS
  - https://doh.pub/dns-query
  - tls://223.5.5.5:853
```
然后在`rules`中加规则指定他们过代理
```yaml
rules:
  # DNS
  - IP-CIDR,1.1.1.1/32,PROXY,no-resolve
  - IP-CIDR,8.8.8.8/32,PROXY,no-resolve
```

不过如果禁用了**Mihomo**的`auto-redirect`和`dns-hijack`选择自己管理DNS转发就不存在这些问题了，当然，缺点就是很麻烦了。

    public-key: "公钥也不给你看" # 对应 Peer 的 PublicKey
